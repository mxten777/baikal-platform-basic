## 2. 개인정보 처리방침 본문

### 1) 처리 목적 및 수집 항목

바이칼시스템즈는 사업 상담·문의 접수와 회신을 위해 이름, 이메일, 문의 내용을
필수로 처리하고 회사/기관명, 관련 프로젝트 및 제품·문의 유형 정보를 선택적으로
처리합니다. 선택정보를 제공하지 않아도 문의할 수 있습니다.
별도의 전화번호 입력란과 첨부파일 기능은 제공하지 않습니다.

문의 처리 과정에서 접수번호, 접수·수정 시각, 동의·보유정책 버전, 처리 상태,
관리자 처리 이력, 알림 처리 상태와 메일 서비스 메시지 식별자를 생성합니다.
관리자 인증은 Supabase Auth를 사용합니다.

### 2) 보유기간 및 삭제

문의 및 관련 처리 이력은 접수일부터 365일간 보관합니다. 상태 변경이나 재시도로
기간을 연장하지 않습니다. 만료 자료는 매일 수행하는 정리 작업에서 삭제하며,
실행 중인 알림 작업의 잠금이나 장애로 지연될 수 있으며 잠금 해소 또는 장애 복구 후
다시 정리합니다. 정리 작업 장애는 담당자가 확인하고 복구합니다.

정보주체의 적법한 열람·정정·삭제·처리정지 요청은 본인확인 및 적용 법령에 따라
처리합니다. 법령상 보존 의무가 있는 경우에는 근거와 기간을 안내하고 필요한 범위만
분리 보관합니다. 전자 기록은 복구·재생이 곤란한 방법으로 삭제합니다.

운영 DB 삭제와 백업 삭제는 동일 시점이 아닐 수 있습니다. 백업 접근을 제한하고
실제 계약·설정에 따른 만료 시 폐기하며, 복구 시 이미 만료되었거나 삭제 승인된
문의가 다시 서비스되지 않도록 접수 재개 전 재삭제합니다.
**백업 보유기간·복구 후 삭제요청 재적용 절차는 운영 계정 확인 후 확정해야 합니다.**

기존 이메일 안내를 통해 접수된 메일과 담당자 회신은 웹 문의 DB와 별도 저장됩니다.
**이메일함·전달본·내보내기 자료의 보유·삭제 기준도 운영 책임자가 확정해야 합니다.**

### 3) 요청 제한 정보 및 서비스 로그

스팸·자동화 공격 방지를 위해 전체 요청·CAPTCHA 검증 예산 및 전체 접수 건수를
제한하고, 이메일을 전체 소문자로 변환한 값의 HMAC으로 보조 접수 횟수를 관리합니다.
접수 경로는 IP 헤더를 읽거나 신뢰·저장하지 않으며 Turnstile Siteverify 요청에도 IP를
별도 전달하지 않습니다. 플랫폼 자체의 IP 처리는 아래 로그·외부 서비스 조건과 별도입니다.
HMAC 자료는 익명정보로 단정하지 않고 접근을 제한합니다.
문의에는 재시도 중복 방지를 위한 payload HMAC도 접수 보유기간 동안 저장됩니다.

전체 요청·CAPTCHA 예산, 이메일 보조 제한 및 전체 접수 카운터의 유효기간은 생성 후
1시간이며 매일 정리하므로 정상 작업 기준
최대 약 25시간 잔존할 수 있습니다. 고객 개인정보가 없는 메일 발송 예산 카운터는
생성 후 2일 만료되며 정리 주기를 포함해 최대 약 3일 잔존할 수 있습니다.

애플리케이션 오류 로그는 오류 코드·무작위 요청 식별자만 기록하도록 구성합니다.
플랫폼 자체의 IP·접속·보안 로그는 각 제공자의 실제 계약·설정을 따르므로,
**Vercel·Supabase·Cloudflare·이메일 서비스의 로그 보관기간과 처리지역은 공개 전
관리자 설정 및 계약에서 확인하여 기재해야 합니다.**

### 4) 외부 서비스 처리

아래는 채택 예정 서비스다. 수탁 법인, 처리 국가·이전 시점·방법·법적 근거,
보유기간과 고지·동의 요건은 실제 계약 확인 및 운영 책임자 승인 후 확정한다.
승인 전에는 해당 처리를 웹 문의 운영에 적용하지 않는다.

| 서비스 | 목적 및 전달 범위 |
|---|---|
| Supabase | 문의 DB·관리자 인증·Edge API. 문의 항목, 동의·처리 이력 및 서버 처리 정보 |
| Vercel | 홈페이지 제공. 접속 및 웹 제공에 필요한 기술 정보 |
| Cloudflare Turnstile | 자동화 공격 방지. 브라우저에서 제공자에게 전달되는 검증 정보와 서버 검증 토큰 |
| Resend | 담당자 알림. 담당자 수신 이메일, 발신 정보, 접수번호·접수 시각·관리자 링크. 고객 이메일·이름·본문은 알림에 넣지 않음 |
| Sentry | 일반 페이지 오류·성능 관찰. 문의 또는 관리자 문의 경로에 방문한 SPA 세션은 이후 이동까지 전송 차단. 일반 페이지의 수집 범위·보유기간은 별도 확인 |

외부 처리자와 국외이전 사항은 계약상 사실로 확정해야 하며,
사용자의 일반적인 수집·이용 동의가 모든 국외이전 요건을 대체한다고 보지 않습니다.

### 5) 안전조치

문의는 익명 직접 DB 조회를 허용하지 않으며, 관리자는 검증된 관리자 권한으로만
조회·처리합니다. 목록에서 이름·이메일·본문을 제외하고 상세 이메일을 기본 숨깁니다.
권한 변경·접근 통제, 전송 보호, CAPTCHA·요청 제한·중복 처리 방지를 적용합니다.
문의 원문을 브라우저 영구 저장소에 저장하지 않으며 접수 재시도 식별자만
sessionStorage에 보관합니다. 문의 관련 Sentry 전송을 차단합니다.

## 3. 승인 후 설정 절차

`INQUIRY_POLICY_JSON`에는 승인된 동일 문서로 아래 필드를 구성한다.

- `version`: `inquiry-2026-10-29-v2` 후보 (전문 승인 후 확정)
- `text`: 1절의 승인된 공개 동의문만 입력. 제작 메모는 제외.
- `privacyText`: 2절의 승인된 처리방침 전문. 승인 필요 표시가 남으면 등록 금지.
- `retentionVersion`: `inquiry-retention-365-v1` 후보
- `retentionDays`: 365 (명시 승인 후)

새 서버는 privacyText 없는 정책도 비활성으로 처리한다.
공개 `/privacy`와 문의 양식은 같은 정책 GET 응답을 사용하며 미승인 문구를
프런트에 하드코딩하지 않는다. 현재 프런트·서버 활성화 설정은 변경하지 않는다.
